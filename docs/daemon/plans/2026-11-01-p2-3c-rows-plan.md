**How this plan is written.** No prototype was built, and the plan embeds no implementation code. The Contracts section holds declarations and the exact strings the tests pin. Every other step states its decision in prose. Executing the plan also tests how well Marshal follows a plan. "As `X` does" means `X` exists and is the model to copy.

**Goal:** every transcript row renders from the wire index, and an expanded row the wire cut gets its whole text from `StackNode` without the render calling the session. Nothing a user sees changes, apart from the edge cases in decision 8.
- `acpwire` gains `WireMessage.truncated`, `NodeDetail.body` and `CompletionDetail.truncated`, and `StackNodeOf` fills them, along with a message's reasoning.
- The settled-row renderer nothing reaches is deleted, with the helpers only it used.
- The TUI caches node detail by version, asks for it after each update, and never calls the session while it renders.
- `drawNode` and every row renderer read `acpwire` payloads: beats and their spine rows, completions, messages, reasoning, run events, receipts, the live reasoning box and a running call outside a beat.
- `browseTree` and `indexTree`, the TUI's index of `viewmodel` nodes, are deleted.
- T1's allowlist loses eight entries across five files, and three keys with them: `symbolrow.go`, `receipt.go` and `runevent.go` (decision 9).

**Non-goals:**
- **The tree stays the TUI's.** The turn walk, node identity, expansion state, regions, browse items, the seen set (`collectSeen`), the completion index, `rowBeats`, the band and the render cache's keys still come from `viewmodel` nodes. Plan 3d moves them to `Session.Stack`. Only node payloads move here.
- **The tray is unchanged.** Its held rows still read the completion index's `viewmodel.CompletionInfo` (plan 3d).
- **No drill-in, callers or browse-action change.** They read the wire index already (plan 3b).
- **No ACP behaviour change** apart from three new optional fields and the new detail on message and run-event nodes.
- **No web change.** The web UI ignores the new fields (spec F4).
- **No changelog entry.**

**Assumptions:**
- Every Go test command below runs with `TMPDIR=/private/tmp/p2-3c-suite`. Create the directory first: `mkdir -p /private/tmp/p2-3c-suite`. Keep the path short: a long one breaks the unix-socket tests in `internal/acp` and `web/bridge`.
- **The base is green.** The full suite passed at `d12762c6` with this `TMPDIR` and `-timeout 20m` (Task 8 has the details). A failure during this plan is new unless it also fails in a detached worktree at `d12762c6`, or it is a known load flake (Task 8) that passes on its own with `-count=3`.
- **T6's goldens never change.** No task runs `TestTranscriptGoldens` with `-update`. Every TUI task's Verify runs the `tui` package, which runs the goldens. No golden fixture holds a text longer than `WireTextCap`, so no golden row asks for detail.

**Decisions this plan makes beyond the spec** (decisions 1 to 7 are also recorded in the spec's revision record):

1. **The renderers take wire payloads; the walk stays.**
   - `drawNode` keeps its `*viewmodel.Node` for the walk, the node's ID and its expansion state. It looks the node's wire form up by key (`m.wire[n.ID.Key]`) and renders from that.
   - A beat's rows are its wire children, in order. A row's `viewmodel.NodeID` is rebuilt as `{KindTool, key}`, as `callerQueryCmds` does (`callers.go:46`), for its expansion state and its click region.
   - The layout reads in `refreshViewport` that look at payloads move too: `narrationOnly`, the tight-block test and `blockTarget`.
   - `refreshViewport` projects the index right after the content-signature check and before it renders, instead of after (`viewport_render.go:200`). A frame whose content did not change still keeps the index it built.
2. **Which expanded rows ask for detail.** Only those the wire cut:
   - a one-call tool row whose call has `truncated` set (its arguments or its output were cut);
   - a completion with `truncated` set;
   - a run event with `truncated` set;
   - a message with `truncated` set (its reasoning was cut).

   Every other expanded row has its whole text on the wire: a beat's narration and thoughts, a group row's subjects and summaries, a thinking row, a message's content, a plan row and a receipt.
3. **Detail comes off the render path.**
   - The render never calls the session. It asks `wantDetail(key, version)`. That returns the detail cached for that node and version, or records the want and returns nil. Until the answer lands, the row draws its wire text.
   - After every message routed through `update` (or through the composer's suspended surface), `Update` batches `detailQueryCmds`. That sends one `StackNode` call per wanted node not already in flight at that version, with the subagent ID the want recorded.
   - The answer is stored under the version it carries. A failed call is stored under the version asked for and marked failed, and is not asked again until the node changes.
   - A stored entry folds into the node's render signature, so its block repaints. Entries for nodes the index no longer holds are dropped whenever the index is rebuilt.
   - The cache is keyed by wire node ID (a string), not `viewmodel.NodeID`. The new file needs no `viewmodel` import, which T1 would refuse, and plan 3d keys everything by wire ID.
   - In-process the answer lands on the next message. Over ACP (P3) the same code waits a round trip while the row shows its wire text.
4. **Running rows never ask for detail.** A running call's output changes on every tick, and its node carries no version (`versionHex`: "the running calls"). A cached answer could not be validated, and a fetch would repeat every frame.
   - Both running renderers draw the wire's text: the last `WireTextCap` bytes of output, and for a call outside a beat the first `WireTextCap` bytes of its arguments.
   - Once the call settles, its row asks like any other.
   - Plan 3b's integration notes listed "a running call's whole output" for 3c. This plan drops it.
5. **What the wire and the detail gain.**
   - `WireMessage.truncated` says the reasoning was cut. `WireTextCap`'s comment already says a capped field sets its node's flag, and the message had none.
   - `NodeDetail.body` is a run event's whole body.
   - `CompletionDetail.truncated` is the completion's own flag: the job dropped earlier output before it was retained. `WireCompletion.truncated` folds that flag together with the projection's two cuts, so a client cannot tell from it whether to say "earlier output dropped".
   - `NodeDetail.thinking` carries a message's reasoning, as one entry with its think time, as it already carries a beat's thoughts.
6. **A cut call's arguments.** `CallDetail.args` is indented JSON. The expanded row's `args:` line shows the detail's arguments compacted with `json.Compact`, or unchanged when they do not parse. The content is whole. The spacing inside the JSON can differ from what the model wrote, and only for a failed call the wire cut.
7. **The settled-row renderer goes with the helpers only it used.**
   - Deleted: `renderCompletedToolCall`, `renderCompletedToolCallIn`, `toolRowHead`, the collapsed diff preview in `toolBody` with its two caps, and the audit branch of `renderTranscriptItemIn`.
   - Also deleted: `symbolrow.go` whole, `toolCategoryGlyph` and its table, and the wrappers `toolTarget` and `fallbackSubject` in `spine.go`.
   - Their tests are ported to the spine row, moved to `viewmodel`, or deleted, each as Task 2's table says. The `viewmodel` functions behind the wrappers keep every test that exercised logic, now calling them directly.
8. **What a user could see differ.** Every case is rare.
   - A beat's reasoning, a thinking row and an expanded call's `error:` line lose control characters and carriage returns, because the wire scrubs them (`ScrubBlock`). Today they reach the terminal raw.
   - A cut call's `args:` line is compacted (decision 6).
   - An expanded running call shows its last `WireTextCap` bytes of output, and a running call outside a beat its first `WireTextCap` bytes of arguments (decision 4).
   - A plan row whose active todo holds a CRLF shows two spaces where it showed one: the wire scrubs before the row flattens.
   - Durations are worked out from Unix milliseconds. A step duration or a think time within a millisecond of a rounding boundary can round the other way.
9. **The allowlist.** T1b does not change: no state read moves.
   - Task 2 deletes the `symbolrow.go` key (the file is gone).
   - Task 4 removes `session` and `registry` from `spine.go`'s entry, and `registry` and `viewmodel` from `transcript.go`'s.
   - Task 6 deletes the `runevent.go` key.
   - Task 7 deletes the `receipt.go` key.

```go
// rowdetail.go (new)

// cachedDetail is one node's StackNode detail, kept for the node version it
// was fetched at. A failed fetch is kept too, so it is not asked again until
// the node changes.
type cachedDetail struct {
	version string
	detail  acpwire.NodeDetail
	failed  bool
}

// detailWant is a render's request for a node's detail: the version it drew,
// and the subagent whose transcript holds the node (0: the session's own).
type detailWant struct {
	version  string
	subagent int64
}

// detailMsg carries a finished StackNode fetch back to the model.
type detailMsg struct {
	key     string // the wire node ID
	version string // the version the render wanted
	res     acpwire.StackNodeResult
	err     error
}

// wantDetail is the detail cached for the node key names at version.
// Otherwise it records the want for detailQueryCmds and returns nil, and the
// row draws its wire text until the answer lands. It never calls the
// session, and it records nothing for an empty version.
func (m *Model) wantDetail(key, version string) *acpwire.NodeDetail

// detailQueryCmds sends one StackNode fetch for every want not already in
// flight at its version, and clears the wants.
func (m *Model) detailQueryCmds() tea.Cmd

// fetchDetailCmd asks the session for one node's detail.
func fetchDetailCmd(ctx context.Context, sess acpclient.Session, key string, w detailWant) tea.Cmd

// handleDetail stores a finished fetch and repaints.
func (m Model) handleDetail(msg detailMsg) (Model, tea.Cmd)

// pruneDetails drops the cached detail and the fetches in flight of nodes the
// wire index no longer holds.
func (m *Model) pruneDetails()

// model.go: Model gains, after callersAsked:
	// details caches StackNode detail for expanded rows the wire cut, by wire
	// node ID, each for the node version it was fetched at. detailWant holds
	// what renders asked for since the last update, and detailAsked the
	// version in flight per node.
	details     map[string]cachedDetail
	detailWant  map[string]detailWant
	detailAsked map[string]string

// steps.go: stepRenderCtx gains, after callers:
	// detail is wantDetail: a node's cached detail, or nil once the want is
	// recorded.
	detail func(key, version string) *acpwire.NodeDetail

// detailOf is the nil-safe form of detail: a context built by hand has no
// cache, and reads as "no detail".
func (c *stepRenderCtx) detailOf(key, version string) *acpwire.NodeDetail
```
