**Goal:** the TUI renders the transcript `Session.Stack` returns. Its tree, node identity, expansion state, regions, browse items, band and completion index come from wire nodes, and drill-in reads the subagent views in `Status`. Nothing a user sees changes, apart from the edge cases in decision 11.
- `acpclient.Session` gains `Stack(subagentID, busy)`. The in-process adapter answers it with the shared projector on the state's clock (`State.Now`, new).
- `acpwire.Subagent` gains `drill`: what a view drilled into the child reads about it.
- The text helpers the TUI borrows from `viewmodel` move to `strutil`. The two only the TUI reads move into the TUI.
- A TUI-local `nodeID` (wire kind and wire ID) replaces `viewmodel.NodeID` in the TUI and in `livebox`.
- `refreshViewport` walks the snapshot. The band, the completion index, `rowBeats`, the seen set, the render cache and browse items all read wire nodes.
- The view stack holds subagent views from `Status`, and `transcriptSource`, the TUI's last handle on a child's state, is deleted.
- T1b gains `Subagent`. T1's allowlist loses ten entries across nine files, and seven keys with them (decision 12).

**Assumptions:**

So drill-in is one level deep, and a drilled transcript names no subagent to drill into.

**Decisions this plan makes beyond the spec** (decisions 1 to 8 are also recorded in the spec's revision record):

1. **`Stack` takes the busy flag until plan 5.** `busy` decides a tree's live beat and whether its turn has a receipt. The TUI owns turns until plan 5, and today it builds every tree, a drilled child's included, with its own `m.busy` (`viewport_render.go:67`). The adapter does exactly that with the flag it is given, whatever `subagentID` names.
   - ACP's `session/stack` keeps its own rule: a subagent's tree is busy while the subagent runs (`acp/stack.go:259-263`). P3 drops the parameter. From then on, a drilled view shows a finished child's receipt while the parent's turn runs.
2. **`Stack` reads the state's clock.** The snapshot's time decides only the band's stale signal (`viewmodel/band.go:178`). The goldens run the state and the model on one clock (`transcript_golden_test.go:82-84`), so the adapter must not read the wall clock. `session.State` gains `Now`, the clock `WithClock` set.
3. **An ID that names no kept child reads as an empty snapshot:** no roots and no nodes, with that `SubagentID`. `Sheet` falls back to the session's own sheet instead, but a drilled frame must never show the session's transcript. An unknown ID is ACP's error case.
4. **No projection cache.** On a session of 2,000 calls (400 beats), measured with throwaway benchmarks:
   - a live refresh already takes 13.9 ms and projects every frame, because the spinner changes the content signature. The projection is 5.5 ms of that, and `ProjectState` costs what the TUI's Build, band and projection cost together. So `Stack` adds nothing while a turn runs;
   - an idle refresh, which skips the projection today, gains about 5.5 ms.
5. **Subagent views carry what a drilled view reads.** `Subagent.drill` holds the child's active root, active route and activity. It is set only while the session keeps the child's state, which is what `Stack` reads, so it doubles as "can be drilled into".
   - A drilled view today reads exactly these from the child's state (`viewport_render.go:80-83, 93, 114-115`): the root a completion row elides, the route a beat's model is compared against (`stepModel`), and the reconnect notice.
   - The route comes from the child's state, not from the view's `Model` and `Provider`. `agent.run` records the provider object's name there (`agent/subagent.go:338`), while a beat's meta compares against the route's provider key.
6. **Drill-in goes by ID.** The view stack holds the subagent's status view as it was when the user drilled in, as it holds the session view today. The breadcrumb and Ctrl+X's "running" check keep reading that snapshot.
   - `drillIntoSubagent(id)` looks the ID up in `Status().Subagents` and pushes the view only when it has `Drill`.
   - The drilled view's facts (decision 5) are read from the live view each refresh, falling back to the snapshot.
7. **Sandbox info moves with plan 4.** Only the running-call row and the approval panel read it. After this plan the row reads the session's own (`m.state.SandboxInfo()` and `m.state.Config.Tools.Shell.AllowNetwork`).
   - A drilled view reads no sandbox info, as today: only `app.go:934` ever sets it, on the root state, so a child's state has none. Plan 4 decides whether a child's shell rows should show the session's.
8. **The text helpers.**
   - `ScrubText`, `ScrubBlock`, `ElideWorkdir`, `FirstSentence` and `StripEmphasis` move to `strutil`, which T1 allows. `viewmodel`, the adapter and the TUI call them there, and `viewmodel` keeps no copy.
   - `ReportTail` (with `ReportTailLines` and `tailLines`) and `BeatRowCap` move into the TUI. Nothing else reads them.
   - The TUI's `failedTailLines` constant is deleted. Only a test read it, and the test reads `viewmodel.FailedTailLines` instead.
   - `viewmodel.IsShellFamily` stays where `viewmodel` uses it. The TUI gets its own `isShellFamily`, and a test holds the two equal.
9. **Node identity is the wire kind and the wire ID.** `nodeID{Kind, Key}` keeps `viewmodel.NodeID`'s field names, so `id.Key` reads unchanged. Its kind is a string from `acpwire`.
   - A final answer's identity kind becomes `final`. `viewmodel` gave the ID the kind `message` while the node itself was `final` (`viewmodel/stack.go:742-745`). Every identity is now built from the node's own kind, so nothing compares the two.
   - The seen set holds every wire node under the turns. It no longer adds the reasoning entries inside a beat or each call inside a merged row. Nothing keys state by those since plan 3c: a beat's reasoning has no region of its own, and a merged row is one node.
10. **What the walk reads.**
    - `refreshViewport` takes the snapshot first. It sets `m.wire`, `m.band`, the completion index and `rowBeats` before the content-signature check. The projection is free now (decision 4), so a frame whose content did not change rebuilds the index too, and `pruneDetails` runs on every refresh.
    - **The welcome banner** shows until the conversation has a turn. That is now true when a root other than `turn:pre` exists (a user turn), or when a node under `turn:pre` is an assistant message, a final answer, or a beat with narration. `Build` keeps every assistant message as one of those (`viewmodel/stack.go:446-480` drops only notice, skill-body and redundant skill-tag messages), so the rule matches today's item scan.
11. **What a user could see differ.** Every case is rare.
    - **Tray todos.** The tray's plan items come from the wire's band, which scrubs todo text. The tray cleaned the raw text itself (`progress.Clean`), which strips a whole escape sequence. Now the wire drops the escape character first, so a todo holding an escape sequence shows its printable remainder (`[1m`), and a todo holding a CRLF shows two spaces where it showed one.
    - **A released child.** A drilled-in child whose state the session releases now shows an empty frame with the welcome banner. That happens only when more than ten newer children finish while you are drilled into an old finished one (`maxRetainedChildStates`). Today the view stack's pointer kept the child alive.
12. **The allowlist.** T1 fails on a stale entry, so each task trims its own:
    - Task 2 deletes the `spine.go` key;
    - Task 3 deletes the `browse_actions.go`, `callers.go`, `click.go`, `expand.go` and `selection.go` keys, and removes `viewmodel` from `browse_inspect.go`'s entry;
    - Task 4 removes `viewmodel` from `viewport_render.go`'s entry and from `browse.go`'s;
    - Task 5 deletes the `browse.go` key. T1b gains `Subagent` at plan `3d`.
