**How this plan is written.** No prototype was built, and the plan embeds no implementation code. The Contracts section holds declarations and the exact strings the tests pin. Every other step states its decision in prose. Executing the plan also tests how well Marshal follows a plan. "As `X` does" means `X` exists and is the model to copy.

**Goal:** the TUI reads its work snapshot through `Session.Work` and lists, inspects and stops work through the session. The work pump moves into the in-process adapter, and the tray, the live box and the Tasks panel render `acpwire` work types. Nothing a user sees changes, apart from the edge cases in decision 12.
- `acpwire` gains the work types. `viewmodel` converts its own work types into them.
- `acpclient.Session` gains `Work`, `ListWork`, `InspectWork` and `StopWork`, and `Changed` fires after each work snapshot the adapter keeps.
- `acpwire.SubagentDrill` gains the child's session ID, so a work item's subagent is found through `Status`.
- `tui.WithWork`, the TUI's work subscription and its pump are deleted.
- T1b gains one name. T1's allowlist loses 11 entries across 10 files, and 8 keys with them (decision 13).

**Non-goals:**
- **No acknowledge call.** Nothing in the TUI acknowledges work (decision 3).
- **No ACP change.** ACP's `Work*Wire` types and `WorkManagerACP` stay in `internal/acp` (decision 1).
- **`viewmodel` keeps its work types and predicates.** The work coordinator and ACP use them.
- **No other C8 group.** Turn control, `Prompt`, the pipelines and the end flow are plans 5b to 5e.
- **No web change.**
- **No changelog entry.**

**Assumptions:**
- Every Go test command below runs with `TMPDIR=/private/tmp/p2-5a-suite`. Create the directory first: `mkdir -p /private/tmp/p2-5a-suite`. Keep the path short: a long one breaks the unix-socket tests in `internal/acp` and `web/bridge`.
- **The base is green.** The full suite passed at `80532121` (117 packages `ok`, no failures). A failure during this plan is new, unless it also fails there, or it is a known load flake (Task 7) that passes on its own with `-count=3`.
- **No golden changes.** No task runs `TestTranscriptGoldens` or the live box's frame tests with `-update`. The TUI's goldens live in `internal/app/tui/testdata/transcript`, and the live box's 27 frames in `internal/app/tui/livebox/testdata`. Every fixture time in both is a whole second, so converting it to Unix milliseconds and back is exact.
- **Production attaches work only when startup found a working provider.** `Run` adds `tui.WithWork(rt)` inside `if n, ok := state.Notice(); !ok || n.Category != session.NoticeProvider` (`app.go:2880`), with the runners. Without it the work lane is inactive, and `/work` leaves "No work in this session." `TestRunWiresSharedWorkService` (`app_test.go:2459`) pins the attached case.
- **A conversation is named by its session ID.** The work coordinator's `conversationID` is its state's `SessionID()` (`runtime.go:3215`), and ACP passes the request's session ID (`acp/watch.go`, `WorkManagerACP.List`).
- **A swap replaces the coordinator before the adapter's session is made.** `rt.NewSession` installs the new coordinator (`runtime.go:2237`) before `seamHost.Swap(state)` runs (`app.go:2959`). The new adapter session therefore subscribes to the new conversation's stream.
- **`session.New` leaves the session ID empty** unless `Persistence.SessionID` is set. A test that needs a child's ID sets it.

**Decisions this plan makes beyond the spec** (decisions 1 to 10 are also recorded in the spec's revision record):

1. **The `acpwire` work types are new, and ACP's stay.** ACP's `Work*Wire` types are the JSON of `viewmodel`'s, so their times are RFC 3339 strings, which C3 forbids. The new types keep ACP's type names without the `Wire` suffix, and ACP's field and JSON names, but times are `int64` Unix milliseconds with `omitempty`. A progress observation is flat, as ACP's is. `WorkQuery` has no conversation: the session names it (decision 5). `WorkTarget` and `WorkAck` are not added.
2. **`viewmodel` converts.** `viewmodel/workwire.go` holds `WorkSnapshotOf`, `WorkItemOf`, `WorkProgressOf`, `WorkPageOf`, `WorkDetailOf` and `WorkStopResultOf`, as `steering.go` holds `SteeringStateOf`. Every conversion makes fresh values: a nil slice or pointer stays nil, and every non-nil pointer (exit code, phase, metric total and rate, prompt, config, progress) is a new pointer to a copy. A zero time is 0. `WorkProgressOf` is exported for Task 4's temporary bridge.
3. **`Session` gains four calls, and no acknowledge.** `Work()` returns the snapshot and whether the session serves work. `ListWork`, `InspectWork` and `StopWork` take the query or task key. All four map to existing ACP methods, so their `Methods` rows are `Exists: true`. The TUI never acknowledges work, so `AcknowledgeWork` is not added. P3 adds it when a client needs it.
4. **The adapter owns the work pump.** `inproc.Deps.Work` is the runtime's `viewmodel.WorkService`.
   - When a session is made, it subscribes first and then reads the seed snapshot, as `startWorkSubscription` did, so nothing published between the two is lost. The seed binds the conversation.
   - It keeps a published snapshot unless the snapshot names another conversation than the bound one, or is older than the kept snapshot of the same conversation. That is `handleWorkMsg`'s rule, moved. It fires `Changed` only for a snapshot it keeps.
   - `Work` returns the kept snapshot. A closed session keeps answering it, as it answers `Status`.
   - `Changed`'s doc comment becomes "fires after anything Status or Work returns may have changed".
5. **A session names its conversation by its state's session ID.** The adapter passes `s.state.SessionID()` as the `WorkQuery`'s and `WorkTarget`'s conversation, as ACP passes the request's session ID. The TUI passed the Tasks panel's conversation (`m.sess.ID()`) or the snapshot's, which are the same value.
6. **The adapter serves work exactly when `Run` attaches it today.** `Run` computes the provider-ready condition once, before it builds `inproc.Deps`, sets `Deps.Work` to `rt` only when it holds, and uses the same value for the runner block. Without `Deps.Work`, `Work` reports false and a zero snapshot, and the three calls fail.
7. **The TUI keeps the last snapshot it applied.** `m.workSnapshot` and `m.workPrevious` stay, so every renderer keeps reading the model. `syncWork`, called from `handleChanged`, applies the session's snapshot, records the previous progress observations and hands the snapshot to an open Tasks panel. `resetWork` starts the view over in `New` and after a swap. A session that serves no work leaves `m.workSnapshot` alone, so tests that set it directly keep working.
8. **The work predicates are TUI-local.** `livebox.WorkActive` and `livebox.WorkNeedsAttention` copy `viewmodel`'s rules over `acpwire.WorkItem`. A test pins them equal to `viewmodel`'s, as plan 3d pinned `isShellFamily`.
9. **The live box converts progress back to measure it.** `progress` is an allowed package (C1), and `progress.EstimateFor` needs two `*progress.Snapshot` values. `livebox/progress.go` gains `progressOf`, which turns a wire observation back into a `*progress.Snapshot`. The box converts the current and previous observations where it measures. `m.workPrevious` and `livebox.Input.Previous` hold wire values. Nothing modifies a snapshot's values once converted, so `notePreviousProgress` keeps the old pointer instead of cloning it.
10. **A work item's subagent is found through `Status`.** `SubagentDrill` gains `SessionID`, set from the child state while the session keeps it. That is exactly when `jumpToWorkOrigin` matched a child before. The jump then reads `m.sess.Status().Subagents`, and T1b gains `Subagents`.
11. **The work calls keep `context.Background()`.** The TUI passes it today, and `m.ctx` can be nil in tests.
12. **What a user could see differ.** Both cases are rare.
    - When two work snapshots land before the TUI reads one, a card's rate is measured across both, so it averages over the longer window. `Changed` coalesces signals, where the pump delivered every event.
    - Times lose their sub-millisecond part. Two progress observations within the same millisecond measure no rate.
13. **The allowlist.** T1 fails on a stale entry, so each task trims its own:
    - Task 4 deletes the `livebox/box.go`, `livebox/livebox.go` and `livebox/running.go` keys;
    - Task 5 deletes the `events.go`, `livebox_view.go`, `steps.go` and `view.go` keys;
    - Task 6 deletes the `pump.go` key, and removes `marshal/internal/viewmodel` from the `todos.go` and `model.go` entries.

// WorkPrompt names a blocked item's request waiting for an answer.
type WorkPrompt struct {
	Kind      string `json:"kind"`

}

// WorkProgressConfig is how an item's progress is produced.
type WorkProgressConfig struct {
	Profile string `json:"profile,omitempty"`
	Source  string `json:"source,omitempty"`

// WorkProgress is one progress observation: the producer's frame, flattened,
// and the times Marshal observed and measured it.
type WorkProgress struct {
	Version         int          `json:"version"`
	Sequence        uint64       `json:"sequence"`
	Phase           *WorkPhase   `json:"phase,omitempty"`
	PrimaryMetricID string       `json:"primaryMetricId,omitempty"`
	Metrics         []WorkMetric `json:"metrics,omitempty"`
	Rows            []WorkRow    `json:"rows,omitempty"`

	Partial         bool         `json:"partial,omitempty"`

// WorkQuery asks for one page of the work list. View is "attention" or
// "history"; Cursor resumes a previous page. The session names the

	View   string `json:"view,omitempty"`
	Query  string `json:"query,omitempty"`
	Cursor string `json:"cursor,omitempty"`
	Limit  int    `json:"limit,omitempty"`
}

// WorkPage is one page of the work list.
type WorkPage struct {
	RuntimeEpoch string     `json:"runtimeEpoch"`
	Revision     uint64     `json:"revision"`
	Items        []WorkItem `json:"items"`
	NextCursor   string     `json:"nextCursor,omitempty"`
}

// WorkDetail is the bounded detail of one item.

	Output      string   `json:"output"`

	Report      string   `json:"report"`

}

// WorkStopResult describes an accepted or refused stop request. The work

	Accepted bool   `json:"accepted"`
}

## Task 1: The work types cross the wire

**Goal:** `acpwire` holds the work types, and `viewmodel` converts its own into them. Nothing uses them yet.

**Files:** `internal/acpwire/work.go` (new), `work_test.go` (new); `internal/viewmodel/workwire.go` (new), `workwire_test.go` (new).

**Steps:**

1. **`acpwire/work.go`** (new) holds every work type of the Contracts, with its doc comment.
2. **`viewmodel/workwire.go`** (new) holds the six conversions (Contracts), under decision 2's rules:
   - every field is copied by name. `ResultRevision` keeps its name. `StartedAt`, `EndedAt`, the snapshot's `ObservedAt`, and the progress observation's `ObservedAt` and `MeasuredAt` go through `acpwire.Millis`;
   - **`WorkProgressOf`** flattens `progress.Snapshot`: its embedded `Frame`'s `Version`, `Sequence`, `Phase`, `PrimaryMetricID`, `Metrics`, `Rows` and `Detail`, then `ObservedAt`, `MeasuredAt`, `Partial`, `Warning` and `ReportedError`;
   - `ProgressConfig` converts from `*progress.Config`, field for field, and `Prompt` from `*WorkPrompt`;
   - nil stays nil, for slices and pointers alike. A non-nil pointer becomes a new pointer to a copy, and a non-nil slice a new slice;
   - `WorkDetailOf` converts its `Item` with `WorkItemOf`, and `WorkPageOf` its `Items`.
3. **Tests.**
