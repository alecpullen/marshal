**How this plan is written.** No prototype was built, and the plan embeds no implementation code. The Contracts section holds declarations and the exact strings the tests pin. Every other step states its decision in prose. Executing the plan also tests how well Marshal follows a plan. "As `X` does" means `X` exists and is the model to copy.

**Goal:** the TUI writes its notes, sets and clears the banner, and runs slash commands through the client seam.
- `acpwire` gains the note, notice and command types: `Note`, `Notice`, `ErrorData`, `CommandInfo`, `CommandListResult`, `CommandResult`, `WireDoc` and `WireRow`, with the role, content-type, notice, command-kind and activity constants. The five command types move out of `internal/acp`, with their JSON unchanged.
- `acpclient.Session` gains `AddNote`, `SetNotice`, `ClearNotice`, `DismissNotice`, `Commands`, `Command` and `CommandAction`. `SessionStatus` gains `Notice`.
- `inproc` gains `Deps.Commands`. A run's provider or login error comes back coded, with its notice.
- The TUI's 138 transcript writes, its 20 notice calls and its command registry go behind the seam. Doc panels render wire docs. `WithCommandRegistry` is deleted, and `WithLogger` is added.

**Non-goals:**
- **No config writes.** The reload paths that clear the provider and config notices (`afterRuntimeReload`, `applyConnectDone`, `reconnectMCPServer`) keep their own `persistAndReload` and reload calls until plan 7. Only their notice calls move.
- **No project data.** `/run`'s outcome doc keeps reading git and the ledger in the TUI until plan 8 (`session/diff`, `session/file`). `sdd_command.go`'s message query stays too.
- **No change to what users see.** Every note keeps its text and order, and every notice its category, hint and timing. The no-runner echo stays a user message (decision 1).
- **No ACP behaviour change.** `session/command` and `session/command_list` return the same JSON. The new `acpwire` fields stay unset on the ACP side until P3.
- **No web change, no changelog entry.**

**Assumptions:**

- **T6's goldens never change.** No task runs `TestTranscriptGoldens` with `-update`. Every TUI task's Verify runs the `tui` package, which runs the goldens.
- **The TUI writes 138 messages**, all through `AddMessage` with `ContentTypePlain`. 135 are `m.state.AddMessage(session.RoleSystem, …)` across eight files: 88 in `model.go`, 16 in `commands_dispatch.go`, 10 in `model_options.go`, 8 in `mcp.go`, 5 in `doctor_secret.go`, 4 in `sdd_scaffold.go`, 2 in `keypress.go` and 2 in `effort.go`. - **The command registry is built once per runtime** (`runtime.go:1838`) and never rebuilt on reload. `Run` hands it to the TUI (`app.go:2756` to `2760`). ACP serves the same registry (`acp/host.go:595`).
- **Only one doc panel is visible at a time.** `dock.Host.Open` replaces the visible panel (`dock/dock.go:78`), and `SwapRetained` keeps at most one displaced panel.
- **`Update` has a value receiver** (`model.go:1672`). A command that runs off the Update goroutine captures the session and context values, never `m`.

**Decisions this plan makes beyond the spec** (all are recorded in the spec's revision record):

1. **A note carries a role, and the no-runner echo is a user note.** Chosen with the user. `AddNote` takes an `acpwire.Note`: its role is system when empty, and only system or user is accepted. With no agent runner, Enter still appends the user's text as a user message and starts nothing (`keypress.go:388`), now through `AddNote` with `RoleUser`. The spec's `AddNote(ctx, text, contentType)` becomes `AddNote(ctx, note)`.
2. **Notes and notice calls do not fire `Changed`.** The TUI repaints after each, as it does today. The runtime's own notices (route, startup, command registration) reach the screen on the tick, as today. A note on a closed session is dropped and logged at debug: the only closed session the TUI holds is the one it is quitting.
3. **The TUI still decides when a notice is set or cleared.** It clears the provider notice when a turn begins, sets a classified notice when a turn or plan authoring fails, clears it on success or cancellation, clears the provider and config notices after its reloads, and dismisses on Esc and when the banner's time is up. Only the calls move. The TTL dismissal still reads and then dismisses, as it does today.
4. **Classification moves agent side, onto the run's error.** `noticeForError` today matches `provider.ProviderError`, `provider.RequestError` and `oauth.ErrAuthRequired` with `errors.As` (`notice.go:20`). Those are agent-side types, and their Go types do not survive a wire. The adapter's run path now returns such an error as an `*acpwire.Error` coded `provider_error` or `auth_required`. Its message is the error's own text, and its data is an `acpwire.ErrorData` holding the notice the TUI built before: same category, message and hint. An error caused by a cancellation (`errors.Is(err, context.Canceled)`) and any other error come back unchanged. The TUI's `noticeForError` takes the notice from the error with `acpclient.NoticeOf`, stamps its source ("turn" or "plan-author"), and falls back to an internal notice as before. Classification sits in `runTurn`, after `callRun`, so every run kind gets it. A plan run's gate check runs inside the run and never sees the coded error.
5. **The command types move to `acpwire`, and ACP's JSON does not change.** `CommandInfo`, `CommandListResult`, `CommandResult`, `WireDoc` and `WireRow` move with their names and tags. They gain fields only the client reads: `CommandInfo.hidden`, `tuiOnly`, `hasHandler` and `promptBody`, `CommandResult.agentGoal` and `WireRow.actionId`. ACP keeps filling only the fields it fills today. Its `kindOf` becomes `commands.Command.Kind`, and its `toWireDoc` becomes `commands.WireDocOf(doc, nil)`, which mints no action IDs.
6. **`Commands()` carries what the dispatch reads.** The TUI branches on a prompt body, on a handler and on the TUI-only flag, in that order (`model.go:6323` to `6370`). ACP's `kind` alone cannot drive that. `/trust` is TUI-only and also has a handler, which runs first. ACP also reports some TUI-only commands as headless because its manager runs them itself. So the info carries `TUIOnly`, `HasHandler` and `PromptBody` beside `Kind`. A prompt command's goal is still composed in the TUI, from the verbatim rest of the line.
7. **`Command` runs the handler agent side, and is called where the handler was called.** The adapter runs it over the session's state with the same arguments. Unlike ACP's `session/command`, it does not refuse during a turn: the TUI never did. The call stays synchronous in `dispatchCommand`, so the result's text is noted before any `AgentGoal` turn starts. A command without a handler returns an empty result.
8. **Row actions get IDs.** A command doc's row actions are Go closures over the state (`/timeline`'s rewind, restore and branch switch, `/branches`' switch, `/context`'s last request). The adapter mints an ID for each action in a result it returns, `a1`, `a2` and on, in row order, depth first. It keeps the actions of the 16 most recent results that minted any. `CommandAction` runs one over the session's state, and its own result's actions are minted the same way. An ID no longer kept returns an error the TUI shows as a note. With one visible panel and one retained, 16 results is ample.
9. **A doc panel renders a wire doc and is given its actions.** `docpanel.New(doc, act)` takes an `acpwire.WireDoc` and a function that turns an action ID into a command. A command doc acts through `CommandAction` on the session it came from. The `/run` outcome doc is built in the TUI, so it acts through its own two actions (branch diff, ledger) until plan 8. The browse help has no actions. The message an action returns carries the same function, so a doc an action opens keeps working. `SetSource` is deleted: nothing calls it.
10. **The TUI gets its own logger.** `WithLogger(*slog.Logger)` sets it; `Run` passes the runtime's logger. Without one, the model logs to a discard logger. The gate's stop warning (`model.go:2276`) and the MCP sign-in engine (`mcp.go:80`) use it.
11. **The wire names the constants the TUI compares.** `acpwire` gains the three roles, the fifteen content types, the six activity kinds, the four notice categories and the two severities, with the session's string values. A test agent side pins them to the session's. `transcript.go` and `viewport_render.go` compare wire strings with them, and `activeSpinnerFrame` takes a string.
12. **Dead code goes.** `livestrip.go`'s `browserStripText` has no caller, so it is deleted.
13. **T1b gains six names, and the allowlist loses 21 entries.** T1b: `AddMessage` and `Logger` (Task 3), and `Notice`, `SetNotice`, `ClearNotice` and `DismissNotice` (Task 4), all at plan `6`. The allowlist loses 21 entries across 17 files, and ten keys go entirely (Tasks 3 to 7 list them).
14. **The new ACP methods are named** `session/note`, `session/notice_set`, `session/notice_clear`, `session/notice_dismiss` and `session/command_action`. `Commands` and `Command` use `session/command_list` and `session/command`, which exist.

```go
	Text        string `json:"text"`
	ContentType string `json:"contentType,omitempty"`
	Role        string `json:"role,omitempty"`
}

// The categories a notice belongs to. Clearing is by category, so a success in
// one subsystem never dismisses another's notice.
const (
	NoticeProvider = "provider"
	NoticeConfig   = "config"
	NoticeTool     = "tool"
	NoticeInternal = "internal"
)

// The severities a notice carries.
const (
	NoticeError = "error"
	NoticeWarn  = "warn"
)

// Notice is the session's banner: one user-facing notice at a time. SetAt is
// Unix milliseconds; SetNotice stamps a zero one with the agent's clock.
type Notice struct {
	Category string `json:"category"`
	Severity string `json:"severity"`
	Message  string `json:"message"`
	Hint     string `json:"hint,omitempty"`
	Source   string `json:"source,omitempty"`
	SetAt    int64  `json:"setAt,omitempty"`
}

// ErrorData is what an Error's Data carries. Notice is the banner a failed
// run's error calls for, classified agent side (C9). Plan 7 adds the provider's
// fields for CodeProviderError.
type ErrorData struct {
	Notice *Notice `json:"notice,omitempty"`
}
```

```go
// The kinds session/command_list reports. A headless command runs through
// session/command, a TUI-only one is interactive and lives in the client, and a

const (

// are what ACP reports today. Hidden, TUIOnly, HasHandler and PromptBody are
// what a client's dispatch reads (plan 6); ACP leaves them unset until P3.

	Description string `json:"description"`
	Args        string `json:"args,omitempty"`
	Group       string `json:"group,omitempty"`
	Kind        string `json:"kind"`
	Hidden      bool   `json:"hidden,omitempty"`
	TUIOnly     bool   `json:"tuiOnly,omitempty"`
	HasHandler  bool   `json:"hasHandler,omitempty"`
	PromptBody  string `json:"promptBody,omitempty"`
}

// CommandListResult is the JSON-RPC result for session/command_list.
type CommandListResult struct {
	Commands []CommandInfo `json:"commands"`
}

// CommandResult is a command's output: plain Text for the transcript, or a Doc
// the client renders as a panel. AgentGoal, when set, is a user turn the client
// submits after rendering Text. ACP's session/command leaves it unset until P3.
type CommandResult struct {
	Text      string   `json:"text,omitempty"`
	Doc       *WireDoc `json:"doc,omitempty"`
	AgentGoal string   `json:"agentGoal,omitempty"`
}

// WireDoc is a command's structured panel.
type WireDoc struct {
	Title     string    `json:"title,omitempty"`
	FullFrame bool      `json:"fullFrame,omitempty"`
	Footer    string    `json:"footer,omitempty"`
	Rows      []WireRow `json:"rows,omitempty"`
}

// WireRow is one entry in a WireDoc. Exactly one shape applies: a section
// header (Header set), an action (ActionID set: Enter runs it through
// CommandAction, and ActionLabel is the right cell), a drill-in (Children
// set), or a read-only title and detail. A row whose action has no ID, as in
// ACP's session/command until P3, shows ActionLabel as plain text.
type WireRow struct {
	Header      string    `json:"header,omitempty"`
	Text        string    `json:"text,omitempty"`
	Detail      string    `json:"detail,omitempty"`
	Desc        string    `json:"desc,omitempty"`
	ActionLabel string    `json:"actionLabel,omitempty"`
	ActionID    string    `json:"actionId,omitempty"`
	Children    []WireRow `json:"children,omitempty"`
}
```
