**How this plan is written.** No prototype was built, and the plan embeds no implementation code. The Contracts section holds declarations only. Every other step states its decision in prose. Executing the plan also tests how well Marshal follows a plan. "As `X` does" means `X` exists and is the model to copy.

**Goal:** a marshal client's run belongs to the session, not to the call that started it.
- The six run calls run their work on the session's context. A call whose context ends (a `$/cancel_request`, a closed connection) answers at once and leaves the run going. Only `session/stop`, the end flow or the session's close stops a run.
- The status says which run is in flight and how the last one ended.
- The service writes a run's outcome note when the run ends, so the note does not depend on its caller still being there. The TUI stops writing it.

**Non-goals:**
- **No change for a client without the capability.** Its turns run on ACP's own `TurnManager` path, which this plan does not touch.
- **No change a user sees in embedded mode.** Esc still stops a run at once. The notes keep their sentences, and the transcript keeps its rows, line for line. The one difference: the cancel note now lands when the run has actually ended, a moment after the TUI goes idle, rather than with it.
- **No reattach, viewer connections, daemon or TUI daemon mode.** Those are plans 3 to 5. The TUI does not read `run` or `lastRun` yet.
- **No change to the run calls' wire shape.** No method is new. `acpclient.Methods` and the registered method count are unchanged.
- **No changelog entry.**

**Decisions this plan makes beyond the spec** (D4 and D6 record them):

1. **The run executes on a goroutine of its own, and does its whole ending there.** The ending is everything `runTurn` and its callers do after the work returns:
   - today's cleanup;
   - `Prompt`'s put-back of a queued text a stop skipped;
   - the outcome note;
   - `lastRun`.

   It then closes a channel carrying the run's result. The caller waits on that channel or on its own context, whichever comes first. So a run whose caller left still puts back its text, writes its note and records its outcome.
2. **The run's context.** The detaching kinds (`turn`, `review`, `agent`, `swarm`, `sdd`) derive it from `s.ctx`. `author` keeps deriving it from the call's context, because only its caller reads its result. `close` cancels `s.ctx`, so a session that a swap or a release closes still ends its runs, as its doc comment promises.
3. **A caller whose context ends returns the context's error,** and nothing else changes for it. The TUI's Esc already stopped the run with `Stop` before cancelling its call. An authoring run whose caller left is cancelled with it, as today.
4. **`run` appears once the run is admitted:** after `BeginWork` succeeds and the stop group is registered, so its ID is the stop group's turn ID. A refused start never sets `run` or `lastRun`. A stop that skipped an admitted run before its work began ends it as `cancelled`.
5. **The outcome, in the order checked:**
   - `gated`: the error carries `CodeHumanGateRequired`, even when stopped, as `stoppedErr` has it;
   - `cancelled`: the slot was stopped, or the error is a context cancellation (`errors.Is` with `context.Canceled`), or the run's own context ended;
   - `failed`: any other error;
   - `done`: no error.

   `lastRun.error` is set for `failed` only, as the error `runError` returns, converted to an `*acpwire.Error` (a coded error as itself, any other as an uncoded one with its sentence).
6. **The cancel note is written only for a user's stop.** The slot gains a flag saying the stop was the session's end. `Release` stops the run through a new unexported stop path that sets that flag; `Stop` uses the same path without it. The note "Agent turn cancelled." is written when the run ends `cancelled`, its slot was stopped by `Stop`, the flag is clear, and the session is not closed. So a release, a close, a swap and the end flow write nothing, as today, and so does an author run whose caller left.
7. **The failure note** is "✘ Turn failed: " for every kind but `author`, whose note is "✘ Plan authoring failed: ", each followed by the first line of the error's sentence. It is written for `failed` only.
8. **The order at a run's end:**
   1. the work returns;
   2. `Prompt`'s put-back runs, and `StartSDD`'s and `AnswerSDDGate`'s plan settles, as today;
   3. the note is written;
   4. under `s.mu`, `lastRun` is set and the slot is released together, so a status read never shows neither or both;
   5. the rest of today's cleanup runs: idle, the stop group, the work, and the context's cancel;
   6. the done channel closes.

   The note is in the state before the response, so the response barrier delivers it to the caller first (P3 R2).
9. **The TUI keeps what is its own.** Its finish handlers stop writing the cancel and failure notes, and keep everything else they do (D6). The refusal note stays the TUI's, because nothing ran.

## Contracts

### The wire (`internal/acpwire/runs.go`, `status.go`)

```go
// RunKind names what a run on the session's run path is (P4 D4).
type RunKind string

const (
	RunTurn   RunKind = "turn"   // session/prompt, a watch resume included
	RunReview RunKind = "review" // session/review
	RunAgent  RunKind = "agent"  // session/agent_run
	RunSwarm  RunKind = "swarm"  // session/swarm_start
	RunSDD    RunKind = "sdd"    // session/sdd_start and session/sdd_answer
	RunAuthor RunKind = "author" // session/sdd_author
)

// RunOutcome is how a finished run ended (P4 D4).
type RunOutcome string

const (
	RunDone      RunOutcome = "done"
	RunCancelled RunOutcome = "cancelled"
	RunFailed    RunOutcome = "failed"
	RunGated     RunOutcome = "gated"
)

// Run is the run in flight. ID is its stop group's turn ID; StartedAt is Unix
// milliseconds.
type Run struct {
	ID        string  `json:"id"`
	Kind      RunKind `json:"kind"`
	StartedAt int64   `json:"startedAt"`
}

// RunResult is the last finished run. Error is set for RunFailed only.
type RunResult struct {
	ID        string     `json:"id"`
	Kind      RunKind    `json:"kind"`
	StartedAt int64      `json:"startedAt"`
	EndedAt   int64      `json:"endedAt"`
	Outcome   RunOutcome `json:"outcome"`
	Error     *Error     `json:"error,omitempty"`
}

// In SessionStatus, after SubagentRunning:
	// Run is the run in flight, nil when none; LastRun is the last finished
	// run, nil until one finishes (P4 D4).
	Run     *Run       `json:"run,omitempty"`
	LastRun *RunResult `json:"lastRun,omitempty"`
```

### The service (`internal/acp/service/turns.go`)

```go
// runSpec says what runTurn runs: its kind, whether it detaches from its
// caller's context, and the work. finish, when set, runs on the run's own
// goroutine after the work returns and before the note: Prompt's put-back.
type runSpec struct {
	kind   acpwire.RunKind
	detach bool
	work   func(context.Context) error
	finish func(stopped, started bool, err error)
}

// runResult is what a finished run reports to the caller still waiting.
type runResult struct {
	stopped, started bool
	err              error
}

// runTurn admits spec's run, runs it on its own goroutine, and waits for it
// or for ctx, whichever ends first. A refusal returns at once, as today. When
// ctx ends first it returns ctx's error and the run goes on (P4 D4).
func (s *Session) runTurn(ctx context.Context, spec runSpec) (stopped bool, started bool, err error)

// stopRun is Stop's body. ending marks the stop as the session's end, which
// writes no cancel note (decision 6). Stop passes false; Release passes true.
func (s *Session) stopRun(cause string, ending bool) error

// runNote is the outcome note a run of kind writes, or "" for none.
func runNote(kind acpwire.RunKind, outcome acpwire.RunOutcome, userStop bool, err error) string
```

The slot gains its run's `acpwire.Run`, set at admission, and an `ending` flag; the session gains `lastRun *acpwire.RunResult`, guarded by `mu`.

## Task 2: Runs on the session's context

**Goal:** a detaching run keeps going when its caller's context ends, and the status reports it while it runs and after it ends.

**Files:** `internal/acp/service/turns.go`, `pipelines.go`, `events.go`, `service.go`, `internal/acp/service/runs_detach_test.go` (new).

**Steps:**

1. **`runSpec` and `runResult`**, as in Contracts. Every caller of `runTurn` passes a spec:
   - `Prompt`: `RunTurn`, detaching;
   - `Review`: `RunReview`, detaching;
   - `RunAgent`: `RunAgent`, detaching;
   - `StartSwarm`: `RunSwarm`, detaching;
   - `StartSDD` and `AnswerSDDGate`: `RunSDD`, detaching;
   - `AuthorPlan`: `RunAuthor`, not detaching.

   Each keeps its own checks before `runTurn`, and its own reading of the result after it.
2. **`runTurn`** (decisions 1 to 4, 8):
   - The slot is taken, and `BeginWork` and `BeginTurnStop` run on the caller's goroutine, exactly as today, so every refusal and every early stop is still answered synchronously and in the same order. The run's context is derived from `s.ctx` for a detaching spec, and from `ctx` otherwise.
   - Right after the stop group is registered, the slot's `acpwire.Run` is set under `s.mu`: its ID is the token's `TurnID()`, its kind the spec's, its start `acpwire.Millis(s.state.Now())`.
   - The work, `callRun` and `runError` run on a new goroutine. So does the ending of decision 8, a stop that skipped the work included. The goroutine sends the result on a buffered channel of one.
   - The caller waits on that channel or on `ctx.Done()`. On the channel it returns the result as today. On the context it returns `false, true, ctx.Err()` at once.
3. **`Prompt`'s put-back moves into `finish`.** `Prompt` passes a `finish` that puts the queued text back when the run was stopped before its work began. The put-back after a refusal (`CodeBusy`, `CodeQuiescing`) stays where it is, since a refusal never reaches the goroutine. The early `return` on `stopped` stays too, but no longer puts anything back.
4. **`lastRun`.** The ending sets it from the slot's `Run`, the end time and the outcome of decision 5, in the same `s.mu` section that releases the slot. For `failed`, the error is `runError`'s result as an `*acpwire.Error`: an error that already is one is kept, and any other is wrapped with no code and its own sentence.
5. **The status.** `Session.Status` reads the slot's `Run` and `lastRun` under `s.mu` and sets the two fields to copies, or leaves them nil. A closed session keeps answering its final value, as every field does.
6. **`stopRun`.** `Stop`'s body moves into `stopRun(cause, ending)`, which also sets the slot's `ending` flag when asked. `Stop` checks `closed` and calls it with `false`. `Release` calls it with `true` in place of its `Stop` call. Neither changes what the stop does.
7. **Comments.** `runTurn`'s doc comment says the run is the session's (P4 D4), and names the one kind that stays its caller's. `Prompt`, `Review`, `RunAgent`, `StartSwarm`, `StartSDD` and `AnswerSDDGate` say a caller that leaves does not stop the run.

## Task 3: The outcome notes are the agent's

**Goal:** the service writes each run's cancel and failure notes, and the TUI stops writing them, with the transcript unchanged.

**Files:** `internal/acp/service/turns.go`, `internal/acp/service/run_notes_test.go` (new), `internal/app/tui/model.go`, `internal/app/tui/provider_error_test.go`, `internal/app/tui/notice_test.go`, `internal/app/tui/pipelines_seam_test.go`, and any TUI test the triage in step 4 changes.

**Steps:**

1. **`runNote`**, as in Contracts (decisions 6 and 7). It returns:
   - "Agent turn cancelled." for `cancelled` when `userStop` is set;
   - "✘ Turn failed: " plus `firstLine(err.Error())` for `failed` of any kind but `author`, and "✘ Plan authoring failed: " plus the same for `author`;
   - "" otherwise.

   The ending computes `userStop` as: the slot was stopped, its `ending` flag is clear, and the session is not closed. It writes a non-empty note with `s.state.AddMessage(session.RoleSystem, note, session.ContentTypePlain)`, at step 3 of decision 8, so the note lands before the slot is released.
2. **The TUI stops writing them.**
   - `handleAgentFinished` drops the cancel note (`model.go:4968`) and the failure note (`:4993`). Everything else in both branches stays: the steering clear and the provider-notice clear on `cancelling`, and the notice and the success-pulse reset on a failure.
   - `handlePlanAuthorFinished` drops its cancel note (`:5137`) and failure note (`:5144`), and keeps the rest.
   - Update both handlers' comments to say the agent writes the run's notes (P4 D6). Nothing else in `internal/app/tui` changes.
3. **The service's tests** in `run_notes_test.go`, reading `state.Messages()`:
   - `TestAUserStopWritesTheCancelNote`: a blocking run stopped with `Stop` ends with exactly one system message "Agent turn cancelled.", written before the call returns (the caller's call has its own context, not cancelled).
   - `TestAFailedRunWritesItsNote`: a runner returning an error whose sentence has two lines writes one system message "✘ Turn failed: " plus the first line. A failing author writes "✘ Plan authoring failed: …".
   - `TestNoNoteForAnEndingOrAGate`: a table. `Release` and `Close` with a run in flight, a runner returning `context.Canceled` with no stop, a run ending gated, and a run that succeeds each write no system message.
   - `TestTheNoteLandsWhenTheCallerLeft`: a blocking run whose call's context is cancelled, then `Stop`. The cancel note is written once `Status().Run` is nil.
