**How this plan is written.** No prototype was built, and the plan embeds no implementation code. The Contracts section holds declarations only. Every other step states its decision in prose. Executing the plan also tests how well Marshal follows a plan. "As `X` does" means `X` exists and is the model to copy.

**Goal:** a client on the daemon's socket asks for a project's session and gets a marshal connection to that session on the project's own child.
- The bridge starts one `marshal acp --viewers` child per project root on first use, and stops it once it has no session.
- `POST /api/projects/attach` upgrades the request to a raw stream, and the bridge relays it, frame for frame, to a viewer connection on the child.
- The bridge's registry follows each session through a `/new` and a close, and `GET /api/daemon` reports the children and their sessions.

**Non-goals:**
- **No TUI change.** The TUI's daemon mode, `marshal attach` and detaching on quit are plan 5. This plan's client is `internal/daemon`'s `Client.Attach` and the scripted test client.
- **No idle-session timeout.** A session leaves the registry only by a close (D3); the timeout is plan 5's.
- **No project environment, trust or pins.** Children run with the bridge's environment (D7, plan 6), the headless trust resolver (D8, plan 7) and no pin (D9, plan 7).
- **No fleet-agent change.** Fleet agents keep their own children until plan 9.
- **No server-profile change.** The attach route exists only on the local profile's socket.
- **No web UI change,** and no event stream for a project child's sessions.
- **No changelog entry.**

**Decisions this plan makes beyond the spec** (D2 and D3 record them):

1. **A project child is a `projectChild`** on the fleet, keyed by the cleaned root, holding its `Child`, its `Registry`, its viewer socket's path, the version its `initialize` reported, and its linger timer.
   - `projectChildFor` starts it on first use, as `control` does. Concurrent first callers share one start. A handshake that fails drops the child and reports its stderr's tail, as the control agent's start does.
   - Its `Child` runs `f.marshalBin` with `--viewers unix://<path>`, in the root (the new `Child.Dir`), with the bridge's environment. Tests inject one through `newProjectChild`.
2. **The viewer socket's path** is `<state>/v/<id>.sock`, where `<id>` is the first 16 hex digits of the root's SHA-256 (D2). The bridge creates `<state>/v` at `0700` before it starts the child.
3. **The handshake on the child** is `initialize` with protocol version 1 and no capability, bounded by `controlHandshakeTimeout`. Its `agentInfo.version` is kept for `GET /api/daemon`. The bridge's own connection then calls only `session/new`, `session/resume` and `session/close` on that child.
4. **The linger.** A project child whose registry tracks no session arms a timer for `projectLinger` (30s) through `afterFunc`. When the timer fires, the child stops and the fleet forgets it. An attach that resolves the child cancels a timer that has not fired. A child that never got a session (its first `new` failed) lingers the same way. `Fleet.Close` stops every project child at once: it stops them, it does not detach them.
5. **The registry's new calls.**
   - `Resume` sends `session/resume` and tracks the ID.
   - `Close` sends `session/close` from the bridge's own connection, which closes the runtime, then cancels the session's waits and untracks it.
   - `rename` moves a tracked session to its replacement's ID, keeping its directory and viewer count.
   - Each `sessionInfo` gains a viewer count and the time it was last active. `attachViewer`, `detachViewer` and `touch` keep them, and `summaries` lists them, most recently active first.
6. **The route** is registered on the socket handler only: `SocketHandler` answers `POST /api/projects/attach` before it routes. `ServeHTTP` never does, so the TCP listener answers it 404 (D3).
7. **The handshake, in order.**
   1. Check the method and the upgrade headers. `Connection` must carry the `upgrade` token, and `Upgrade` must name `marshal-acp`, both case-insensitively.
   2. Decode the body, and check that the root is absolute and a directory.
   3. Resolve the project child.
   4. Resolve the session:
      - none: `New` with the root as its directory;
      - a tracked ID: as it is;
      - an untracked ID: `Resume`.
   5. Dial the child's viewer socket. A dial that fails after a `new` closes that new session again.
   6. Hijack the connection, clear its deadlines, and write `101 Switching Protocols` with `Connection: Upgrade`, `Upgrade: marshal-acp` and `Marshal-Session: <id>`.
   7. Count the viewer, and start the relay.

   The refusals, each with a JSON `{"error": …}` body:

   | Refusal | Status |
   |---|---|
   | A wrong method | 405 |
   | Missing upgrade headers, a bad body or a bad root | 400 |
   | A resume that fails | 404, through `ErrUnknownSession` |
   | A child that cannot start, or a dial that fails | 502 |
   | A response writer that cannot hijack | 500 |
   | A server without a fleet | 501 |
8. **The relay** (D3).
   - It runs two pumps. Each reads frames at newlines up to `maxFrameBytes`, and writes each frame, newline included, unchanged to the other side. The TUI-side pump first forwards whatever the hijacked reader had buffered.
   - A frame over the cap, a read error or EOF on either side closes both connections. Closing ends the other pump.
   - **What it watches.**
     - It decodes each TUI frame's ID, method and the two parameters it needs. A `session/new` with `replaces` is watched as a replacement; a `session/close` is watched as a close, with its `sessionId`.
     - While a watch is waiting, it decodes each agent frame's ID, result and error. A successful answer to a watched replacement renames the session to the result's `sessionId`, and the relay follows the new ID. A successful answer to a watched close is forwarded first, and then the bridge closes the session through its own connection (decision 5) on a goroutine of its own. An error answer clears the watch and changes nothing.
     - IDs are compared by their compact JSON.
   - Every frame relayed either way touches the session.
   - When the relay ends, the viewer is uncounted and the session touched. A close that left the registry empty arms the linger.
   - It logs the attach and the detach with the root, the session and the reason, and never a frame's params (P3 R8).
9. **`GET /api/daemon` gains `children`:** for each project child, sorted by root, its root, its version and its sessions' summaries. `internal/daemon`'s `Info` mirrors them.
10. **The client's half.** `Client.Attach` dials the socket, writes the request with the two headers and the JSON body, and reads the response with the standard reader. Then:
    - a `101` that names `marshal-acp` and carries a session ID returns an `Attachment`, whose stream reads the reader's buffered bytes before the connection's;
    - any other answer returns an `*AttachError` with its status and its body's `error`.

    The caller's context bounds the handshake only. Its deadline is cleared on the connection before the stream is returned.
11. **The end-to-end proof** (task 6) is a new `test/daemon` package. It runs a real bridge in the test process and a real child, the test binary itself, re-run as `acp --viewers` through `acp.RunWithViewers`. A scripted client drives it with `Client.Attach` and `rpc.Dial`. Setting `MARSHAL_DAEMON_TEST_MARSHAL` to a built `marshal` binary makes the bridge supervise that binary instead, which the smoke run uses.
