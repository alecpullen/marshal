**How this plan is written.** No prototype was built, and the plan embeds no implementation code. The Contracts section holds declarations only. Every other step states its decision in prose. Executing the plan also tests how well Marshal follows a plan. "As `X` does" means `X` exists and is the model to copy.

**Goal:** a daemon session on a project whose config is not trusted asks its TUI, as embedded mode does, and applies a trust to the running session without ending the TUI's program.
- A project child lets the session's marshal client answer the trust question for every session the bridge opens for an attach.
- A trust is recorded as embedded mode records it, and the session's config is reloaded in place.
- `launch` no longer keeps an untrusted project embedded, and `marshal attach` no longer refuses one.

**Non-goals:**
- **Embedded mode is unchanged.** Its trust panel still records the decision and ends the program, and `launch` still restarts the runtime with the project config in force (W6).
- **Fleet agents and the control agent keep the headless rule.** Neither runs on a project child yet (D10 is plan 10).
- **Project plugins do not reload in place** (H10).
- **No watching of the trust store or config files** while a session runs (H5).
- **No changelog entry.**

**Decisions this plan makes beyond the spec** (D8's details block records them):

1. **The mark is the registry's.** `Registry.ClientTrust` makes `New`, `Resume` and `resumeAll` send `clientTrust: true`; only a project child's registry sets it. A per-session mark waits for plan 10, which puts other sessions on that registry.
2. **`app.WithClientTrust` wins over a resolver.** The child keeps appending the headless resolver to every runtime, and the option makes the runtime ignore it, so nothing in `viewers.go`, `run.go` or `listen.go` changes.
3. **The trust calls are a marshal client's.** A client without the capability reads no prompt and has its decision refused.
4. **The prompt says how a trust applies.** `trust/prompt` answers `inPlace`, and `TrustPrompt` returns the whole result on both arms of the seam. No method is added, so the method table is unchanged.
5. **The in-place apply lives in `internal/app`,** behind a new `service.Deps.ApplyTrust`, because the runtime owns the store's location, the reloader and the session state. The service keeps the validation and the settled flag. Embedded mode never sets `ApplyTrust`.
6. **The apply's order:** load the trusted layers, record, mark trusted, reload, replace the layers, write the note. A failure before the reload changes nothing; a failed reload unmarks the session, and a recorded permanent trust stays recorded. Every failure writes "✗ Trust not applied: " and the error's first line.
7. **The panel defers an in-place decision to the model's call queue.** The in-place panel calls nothing; it sends a message, and the model makes the `trust/decide` call off the Update goroutine, because a reload over the relay can take seconds.
8. **One answer wins.** After a trust the prompt answers no directory, and a later answer to it succeeds without effect. A decline records nothing and leaves the prompt pending, as in embedded mode.
