**Goal:** a project the user pins keeps its daemon child running with no session, and keeps that project's index current.
- `marshal daemon pin [dir]` and `marshal daemon unpin [dir]` change the daemon's pins.
- A pinned project's child holds its project host open through `project/hold`, with the index watcher on.
- `GET /api/daemon` and `marshal daemon status` show the pins.

**Non-goals:**
- **No web UI change** (H12). The project settings `PUT` is untouched.
- **No pinning under the server profile.** The route is the socket's only, and so are project children.
- **Language servers and embeddings keep their rules** (design §4.3). A pin does not start a language server, and its index passes embed as a session's do.
- **No new config setting.** A pin is the daemon's state, in its fleet registry.
- **No changelog entry.**

**Decisions this plan makes beyond the spec** (D9's details block records them):

1. **Pins are a list of their own** in the workspace file, not a `ProjectSettings` field. The settings `PUT` replaces a project's settings whole and would drop a pin, and removing a registered project would delete one. A pin needs no registered project.
2. **The workspace is the pin's one source of truth.** A project child asks it whenever it would arm a linger and after every handshake. So a pin made before its child starts, a restart and the daemon's own start all take one path, and the bridge keeps no pin state of its own.
3. **One route, on the socket only:** `POST /api/projects/pin`, with `pinned` true or false.
4. **A pin that cannot start or hold its child stays pinned,** and the error is answered. The daemon's next start retries it, and `unpin` drops it.
5. **On the agent side a hold is per root and idempotent.** The agent host keeps one release per held root, and drops all of them when it closes.
6. **A hold loads its config by the headless rule,** as the child's runtimes do, and never replaces a config that a session has given the host.
7. **The watcher follows the hold through the index key,** so taking or releasing a hold restarts the index work only when it changes whether the watcher runs.
8. **Only a `--viewers` child serves the hold methods,** on the bridge's own connection. A viewer is refused as its lifecycle calls are, and every other `marshal acp` answers that the method does not exist.
9. **The daemon starts pinned children in the background** after the fleet's reattach, one after another, so a slow environment does not delay the socket.

## Contracts

### The held project host (`internal/app`)

```go
// host_hold.go
// Hold holds root's project host open with no session (P4 D9). The host is
// opened if it is not, its index work starts as a session's attach starts it,
// and its watcher runs while any hold is taken, whatever cfg's indexing.watch
// says. cfg becomes the host's config only when no session has given it one.
// The release is safe to call more than once; the last release lets the host
// linger as a session's does.
func (hs *Hosts) Hold(root string, cfg config.Config) (release func(), err error)

// hold registers one hold and, when no session has attached, makes cfg the
// host's config and projectID its project, then refreshes the index work.

// unhold drops one hold and refreshes the index work.
func (h *ProjectHost) unhold()

// On ProjectHost, guarded by mu:
	// holds counts the holds not yet released (P4 D9).
	holds int

// hosts.go: the watcher is the hold's or the config's.
// watchFor reports whether a host's index watcher runs: always while the host
// is held (decision 6), else as config.WatchEnabled says.
func watchFor(cfg config.Config, held bool) bool
func (h *ProjectHost) supervisor(cfg config.Config, held bool) indexSupervisor
```

## Task 1 — the held project host

**Files:** `internal/app/hosts.go`, a new `internal/app/host_hold.go`, a new `internal/app/host_hold_test.go`, `internal/app/hosts_test.go`.

1. `watchFor` is true when `held`, and otherwise `config.WatchEnabled` with the embedding route, as `supervisor` computes it today. `supervisor` and `indexKeyFor` take `held` and use `watchFor`. `refreshIndex` and `startIndex` pass `h.holds > 0`, read under `h.mu` where they already read `h.cfg`. A change in whether the host is held then changes the key exactly when it changes the watcher (decision 7).
2. `Hosts.Hold`: acquire the host as a runtime does, at the current time. Read or create its project row on the host's own database (`GetOrCreateProject` with `cfg.Project.Name`), and call `hold`. A failure after the acquire releases it. The returned release runs once: it calls `unhold` and then `release`.
3. `hold`, under `h.mu`: count the hold. When no session has attached yet, take `cfg` as the host's config and the project ID as its project, and mark the host attached, so `refreshIndex` starts the index work. A host a session has already attached keeps its config and its project (decision 6). Then `refreshIndex`. A closed host does nothing.
4. `unhold` drops the count and calls `refreshIndex`. A host released by its last session while still held keeps its index work, because the hold's reference keeps it open.
5. The existing call in `TestHostStartsTheWatcherOnlyWhenConfigured` passes `held` as false.
6. Tests in `host_hold_test.go`, with `testHosts`, `hostRoot`, `countingWorker` and `waitForRuns`:
   - `TestAHeldHostWatchesWhateverTheConfigSays`: `supervisor` with `held` true watches with `indexing.watch` unset and with it set false.
   - `TestAHoldStartsTheIndexWithNoSession`: on an indexing registry with a counting worker, `Hold` with no session runs the index work once.
   - `TestAHoldRestartsTheIndexOnlyWhenItChangesTheWatcher`: a session attaches with the watcher off (one run); a hold starts a second run; a second hold starts none; releasing one of two holds starts none; releasing the last starts a third.

## Task 4 — pinned project children

**Files:** a new `web/bridge/pins.go`, a new `web/bridge/pins_test.go`, `web/bridge/projectchild.go`.

1. `pinned` reads `IsPinned` from the fleet's workspace.
2. `armLinger` arms nothing for a pinned root, and its `fire` keeps a pinned child as it keeps one with sessions, checking the pin again when it fires (decision 2).
3. `holdLocked` sends `project/hold` with the root on `pc.child`, bounded by its context, and returns the error.
4. In `startProjectChildLocked`, after a successful handshake, call `holdLocked` when the root is pinned. In `reinitProjectChild`, after its handshake, do the same, so a restarted child holds again. In both places a hold that fails is logged at warn with the root and the error, and does not fail the start, so an attach is never refused because of a pin.
5. `Fleet.Pin`:
   1. Clean the root. Refuse a relative root, and for a pin a root that is not an existing directory, with an error the route maps to 400.
   2. Record the change with `SetPinned`.
   3. To pin: resolve the project's child with `projectChildFor` (which starts it, cancels its linger and, now that the root is pinned, holds it). Then call `holdLocked` under the child's lock, because a child that was already running when the pin arrived has not held it yet. A hold on a held root changes nothing on the agent side. Answer pinned and running. An error from either step is returned, and the root stays pinned (decision 4).
   4. To unpin: when a child is live for the root, send `project/release` under its lock and log a failure, then `rearmLinger`, which arms the linger for a child with no session. Answer not pinned, and running when a child is live.
6. `StartPinned`: for each pinned root that is an existing directory, resolve its child with `projectChildFor` under `controlHandshakeTimeout`. Log a root that is not a directory, and a start that fails, at warn, and go on. It stops early when `ctx` ends.
7. Tests in `pins_test.go`, with `projectFleet`, `captureTimers` and `projectEntry`:
   - `TestPinningStartsAndHoldsTheChild`: `Pin` on a root with no child starts one, and the fake records `project/hold` with that root on stdio. The answer is pinned and running.
   - `TestAPinnedChildArmsNoLinger`: after the pin, no linger timer is armed; an attach-like `New` and `Close` on its registry followed by `rearmLinger` arms none either.
   - `TestPinningARunningChildHoldsIt`: a child started by an attach, then pinned, records a hold.
   - `TestARestartedPinnedChildHoldsAgain`: `die` on the fake's generation; the new generation records `project/hold` after its `initialize`.
