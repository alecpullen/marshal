## Goal

- **`marshal fleet add` and `marshal fleet remove`** write `fleet.toml`
  without losing its comments.
- **Settings › Hosts adds, removes and signs in to a host** in a native build.
  The token reaches the CLI on stdin only.
- **The registry forgets a removed host,** and every store and section drops
  it.
- **New work chooses the host it runs on,** and the thread it starts opens
  there.

## Non-goals

- Relayed hosts, `fleet add --relay`, and a browser's sign-in: plan 4.
- Adding a `token_cmd` profile from the Studio (spec D7).
- Editing an existing profile's URL or CA file. Remove it and add it again.

## Decisions this plan makes beyond the spec

1. **Table headers `fleetprofile` edits.** A server's table is the line
   `[servers.NAME]` or `[servers."NAME"]`, with optional spaces inside the
   brackets and an optional trailing comment. `RemoveServer` finds exactly
   one such header for the name and deletes up to the next line starting
   with `[`, or the end of the file. When there is no such header, but the
   file still defines the name, it refuses (spec D6).
2. **What `AddServer` writes.** It writes one blank line, then the header,
   `url`, `ca_file` when set (as given, so a relative path stays relative to
   the file), and `notify = false` only when notifications are off. It
   writes no `token_cmd`.
3. **`fleet remove` asks nothing.** It is a command for a program and a
   person alike. The Studio confirms before it runs it.
4. **The runner's words.** A command that fails throws `FleetProfileFailure`
   with the last non-empty line of its stderr, or "marshal exited <code>"
   when stderr is empty.
5. **Adding is two commands, and the second can fail alone.** When `add`
   succeeds and `login` fails, the form closes as added. The host's detail
   then shows the login's words beside Sign in (spec Error handling).
6. **The new-work routes are bundled per host.** `NewWorkRoutes` holds the
   closures `forProject` builds today. The model holds one per host and
   switches them when the Host chip changes, so the dialog never needs a
   second model.
7. **Changing host reloads the lists.** Issues, recipes, recent prompts and
   the project menu are re-read from the new host. The prompt and the kind
   are kept.

## Task 1 — `fleetprofile` adds and removes a server

**Files:** `internal/fleetprofile/edit.go` (new),
`internal/fleetprofile/edit_test.go` (new).

1. **`AddServer`:**
   - Check the name with `checkName` and the URL with `checkURL`. Refuse a
     server with a `TokenCmd`: the Studio never adds one.
   - Read the file as `Load` does, privacy check first. A missing file is
     empty: create its directory `0700` and treat its text as empty.
   - Refuse a name the loaded file already has: "NAME is already in
     fleet.toml".
   - Append the table (decision 2), and decode the new text with `decode`.
     If it does not decode, return that error and write nothing.
   - Write it atomically at `0600`.
2. **`RemoveServer`:**
   - Load the file. Refuse a name it does not have, with `Lookup`'s words.
   - Find the table (decision 1). With no header of its own, refuse: "NAME
     is not defined by its own [servers.NAME] table; edit <path> by hand".
   - Delete it, check the result with `decode`, and write it atomically at
     `0600`.
   - Then delete `KeychainKey(name)` through `open`. A missing entry is
     success, and a keychain that cannot be opened is reported after the
     file has been written.
3. Tests, in `edit_test.go`, using a temporary home and an in-memory store as
   `token_test.go` does:
   - `TestAddServerAppendsAndKeepsComments`;
   - `TestAddServerCreatesAPrivateFile`;
   - `TestAddServerRefusesADuplicate`;
   - `TestAddServerRefusesABadURL`;
   - `TestAddServerWritesNotifyOnlyWhenOff`;
   - `TestRemoveServerDeletesOnlyItsTable`;
   - `TestRemoveServerAcceptsAQuotedHeader`;
   - `TestRemoveServerRefusesAnInlineTable`;
   - `TestRemoveServerDeletesTheToken`;
