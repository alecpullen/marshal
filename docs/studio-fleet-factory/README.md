### Implementation status

This redesign is delivered, not pending. Each slice's evidence is in §16 of the design.

- **Slice 1 — Fleet home and responsive navigation: implemented and verified in browsers.** Browser checks at desktop 1440×900, tablet 768×1024 and phone 390×844: 63 cases, 54 pass, 9 fail, the 9 being the known baseline below. All 45 new cases pass at all three widths; the Fleet axe scan passes in both themes at every width and asserts no horizontal overflow, pinning the two palette defects it surfaced in `web/ui/src/app.css` and `web/ui/src/lib/ui/Button.svelte` until that palette is fixed. Screenshots, copied to the gitignored `.docs-archive/studio-uiux/`: `fleet-desktop.png`, `fleet-tablet.png`, `fleet-phone.png`.
- **Slice 2 — project factory dashboard and handoff: implemented and verified in browsers.** Same suite, same three widths: 99 cases, 87 pass, 12 fail on the run before a stale case was repaired — the 9 baseline cases plus one stale assertion in `project-settings.pw.ts` that task 15 updated in place. That repair returned the suite to the 9-case baseline, which is the state slice 3 inherits. All 36 slice-2 cases pass at every width, alongside a manual 200% browser-zoom smoke check of the factory and handoff. Screenshots: `factory-desktop.png`, `factory-phone.png`, `handoff-desktop.png`, `handoff-phone.png`, `draft-phone.png`.
- **Slice 3 — execution, decisions and recovery, CI-first review, and agent return paths: implemented and verified in browsers.** Same suite: 150 cases, 139 pass, 2 skip, 9 fail, the 9 being the same baseline and the 2 skips the 200% zoom case at the two widths it does not measure. All 17 slice-3 cases pass, with the zoom case asserted at desktop and skipped at the other two widths. Screenshots: `execution-desktop.png`, `execution-phone.png`, `decision-phone.png`, `recovery-desktop.png`, `ready-review-desktop.png`, `ready-review-phone.png`.

Unit and type baselines are unchanged across the redesign: as the last slice records, `npm test` reports 1154 passing and `npm run check` the same 5 errors and 1 warning in the same 6 files as before it.

**Known baseline browser failures.** Three `project settings` cases — `role overrides follow the agent default independently and reset`, `a stale save warns, keeps the edit, and offers reload`, and `unsaved edits are confirmed before in-app navigation` — fail at all three viewports because the credential-free fixture bridge serves no model profiles, so the "Model profile" select offers no `gamma` option. They are pre-existing, reproduced at the base commit `f42a7c59` at the two widths that existed then, and recorded in §16. No other case fails.

**What the browser evidence proves.** The mocked-presentation cases answer the fleet, inbox, project factory, handoff and session reads from Playwright fixtures. They are evidence about rendering and navigation only — never live agent execution, a real session event, or a factory state the bridge accepted or persisted. The isolated fixture bridge has no GitHub credential and `factoryAPI.preflight` requires one, so no create, approval, retry or recovery reaches the bridge in any case.

**Planned, not implemented.** The planning workspace, voice capture, the extensible workflow editor, host management, richer connection and environment flows, merge, and cross-device continuity remain product direction. They are reachable in the Studio UI as roadmap pages, which a real-bridge browser case asserts are planned and read-only; appearing there is not the same as being implemented.

## Relationship to the bootstrap implementation

[PR #57](https://github.com/alecpullen/marshal/pull/57) implements the narrowly scoped first factory loop. Its docs/bootstrap-factory documents describe the implementation and its current acceptance limits. Bootstrap documents preserved here are the original planning drafts; their draft-status wording records their historical state and is not a claim that implementation has not since occurred.

The broad design is a product direction, not a promise that every described feature is implemented or an instruction to build the entire vision before using the bootstrap loop. No new mockups or product decisions were introduced when preparing this archive. Source snapshots, temporary tooling, execution ledgers, credentials and implementation review artifacts are excluded.
