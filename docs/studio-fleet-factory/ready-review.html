01 · The issue and approach

An approval outlives its connection

Disconnecting deleted the connection’s pending requests. The transcript returned on reconnect; the unanswered approval did not.

The session now owns those requests. Connections subscribe to its state, so reconnecting retrieves the same outstanding approval.

Copying requests during reconnect would leave a gap while no client is attached. Session ownership removes that gap without making a connection responsible for recovery.
02 · Why the repair matters

Only one answer can settle the request

Moving ownership exposed a race: two clients could both read an approval as pending and submit different answers.

Checking and settling now happen under the same session lock. The first answer resolves the request; later answers receive its settled state instead of executing it again.
