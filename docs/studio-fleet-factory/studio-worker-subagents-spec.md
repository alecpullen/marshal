# Studio worker subagents: implementation specification

Date: 2026-11-16

Status: specification for the [approved design](studio-worker-subagents-design.md). Implementation follows the [plan](plans/2026-11-16-studio-worker-subagents-plan.md).

## Existing behavior and scope

Factory implementers and reviewers are Marshal sessions launched by `SpawnFactoryWorker`; their child agents are owned by those sessions. `buildAgentRunnerWithLock` registers Marshal's `agent.run` and related tools. Children share the parent's working tree, inherit a bounded live authority, and cannot spawn nested children. The default concurrency is three per session. Studio already drills into child stacks via `AgentConversation`, and ACP exposes `session/subagent_cancel`. Factory parking checks `session/end_work`, but `factoryWorkers.Execute` currently parses the parent's final report as soon as its turn ends. These pieces do not establish that a real factory turn using subagents works end to end.

Deliver reliable Marshal worker delegation, shared Fleet/Factory subagent visibility and control, per-role and per-item configuration, and factory waiting/continuation. Preserve existing ordinary sessions, independent factory review, workspace and permissions. ACP-backed non-Marshal workers are capability-dependent; unsupported or unknown capabilities are shown as unavailable. No new generic worker backend or nested subagent support is required.

## Configuration and inheritance

Add independently inheritable enablement, model and concurrency values for each factory role. A missing override inherits; explicit false is distinct from missing. Resolve each field in order: current Marshal project/session defaults, project factory role override, work-item role override. Show effective value and source; reset removes the override. Drafts re-resolve inherited fields when source settings change, retaining explicitly overridden fields. A review displays the resolved settings and source versions. Approval atomically validates those source versions and snapshots resolved values into the approval revision; conflicts refresh the review. Active runs continue using their approved snapshot. Changing them uses the existing work-item revision and approval flow.

The default delegation behavior, child model resolution and maximum concurrency must match an ordinary Marshal session. Model override absent means use the runtime's normal subagent route; do not replace that with the implementer's model. Existing runtime limits apply, including its concurrency cap. Persist both overrides and resolved settings; use an explicit optional value to distinguish inherit from false/zero. Add a narrow agent-side capability/configuration seam to report defaults and apply a per-session snapshot through ACP at session creation; do not modify project config or global runtime defaults. If the runtime cannot report or enforce a requested setting, show unsupported and reject approval/start rather than pretend it is in force. Old work items with no fields preserve existing behavior.

## User interaction

In Factory, show each worker and its children with role, task, status, and link to the worker session. In Fleet, the ordinary agent session provides the same child interaction. In a parent transcript, retain the existing child entry and drill-down. In the child view, show parent breadcrumb, task, state, transcript/report and user actions. Provide direct steering and stop for a running child, with clear pending, accepted, failed and unknown outcomes. Desktop may use existing pane layouts; on a phone the path is stacked and back navigation returns to the previous position. Use existing TUI vocabulary and status semantics; distinguish implementer-owned review children from the factory reviewer. Preserve keyboard and screen-reader access and never convey state only by color.

Steering is a user-originated operation addressed by session ID, child ID and unique request ID. At the child owner, validate it is the intended live child, enqueue the user's instruction through Marshal's steering mechanism, record the instruction in child-visible activity, and queue a parent-visible notice containing the child identity and instruction. Accepting the request does not claim the model has consumed or acted on it. Retries with the same ID and text return the original receipt; same ID with different target or text conflicts. If the child finishes in a race, return a clear rejection or uncertain receipt, never silently target another child. Do not mutate or duplicate on a lost response. Project/session authorization and the inherited policy ceiling remain in force.

Use the existing child-cancel seam for stopping. Its acknowledgement means a stop was requested, not that the child has stopped; observe terminal status before presenting stopped. A failed, disconnected or unobservable operation remains failed or unknown, and no unrelated session is affected. If child control, history or identity cannot be observed for a backend, disable the corresponding control with an explanation; retain any known history with freshness indicated. No new permission is implied by a planner or MCP grant.

## Factory coordination and recovery

After a worker turn returns, do not accept its final report while child activity remains running or unknown. Persist the original effect, worker/session identity, turn/result evidence and a `waiting_delegated` stage, then show **Waiting for delegated work**. Observe the same worker's child work through the session owner; do not confuse its children with unrelated jobs or other sessions. A final report from before children settled cannot prove their results were incorporated.

When every child associated with the effect is observed terminal, including failed or user-stopped children, automatically journal and dispatch one continuation prompt to the same worker. The continuation tells the worker to incorporate available reports, assess failures or ask for input, and emit the required factory report for the same effect and candidate. Recheck authority, session and checkout identity. A continuation that launches more children repeats this wait-and-continue cycle; apply existing bounded iteration and recovery rules, never bypassing factory gates. Accept a fresh valid report only when the turn ended successfully and its child set is observably settled. When no child was launched, preserve current single-turn behavior.

Record continuation intent and dispatch before sending. A duplicate tick must not start another continuation. On restart or lost reply, reconcile the same session's turn identity, transcript, child state and matching effect before accepting a result; if dispatch or delivery cannot be proven, surface existing recovery/needs-input state rather than sending another prompt. A stopped worker cancels or accounts for its own children using existing session lifecycle mechanisms and remains stopping until their actual terminal state is observed. Never affect other sessions or silently clean up their workspaces. Independent reviewer authority, candidate SHA and existing tests/CI checks remain unchanged.

## Verification

Use isolated deterministic model, session, forge and repository fixtures. Cover default and overridden settings, approval races and restart, disabled and unsupported capabilities, direct steering and parent notification including replay and target races, cancel acknowledgement versus observed stop, two sessions with the same child ID, child transcript navigation, and mobile/keyboard use. Exercise a real Marshal factory implementer and reviewer delegating through `agent.run`; hold advancement for running and unknown children, continue after success/failure, reject stale reports, recover at each dispatch boundary, and verify unrelated work and independent review remain intact. Report any live-model or external ACP-agent tests separately. The web layer remains standard-library only and must not import `internal/`.
