## Context

Since F2 the bridge has served two Studios: Svelte at `/` and Flutter at
`/next/`. The Svelte one has been frozen since F2. This phase makes Flutter
the Studio and removes the other, with its toolchain.

Today `web/bridge/assets.go` embeds `web/bridge/static`, which
`npm run build` in `web/ui` writes; CI's web job runs `npm ci`, `npm test`
and `npm run build` and checks that the build leaves no untracked file in
`static`; `scripts/e2e/run_browser_checks.sh` drives the Svelte Studio in a
browser; `web/ui/src/lib/contract.ts` is generated by `tsgen`. The public
status page (`web/bridge/status.go`, `status_page.html`) is plain HTML and
is not part of either Studio.

## Goal

- The Flutter Studio is served at `/`.
- No Svelte, TypeScript or Node remains in the repository.
- A release builds and ships the Studio with Flutter alone.
- Every document that describes the Studio describes this one.

## Non-goals

- New features.
- Native mobile builds. They are the next programme.
- Changing the status page.

## Decisions

1. **The cutover is taken; the size exception is accepted (2026-11-17).** A
   first draft of this phase deferred the cutover, because the trial build's
   first load is 6.9× the Svelte Studio's raw and 8.3× gzipped against the 3×
   ceiling decision 6 sets. The ceiling was raised before removal, as decision 6
   requires, and the cutover was then taken anyway: the Studio is what the
   programme is for, and a frozen second client costs more than the bytes. Two
   facts narrow the gap — a browser that has CanvasKit cached from any other
   Flutter site fetches none of the 7.4 MB engine, and the app-served figure
   alone is 2.55×. What the numbers did change: `--no-web-resources-cdn` is
   mandatory in every build, so the engine comes from the bridge rather than
   gstatic, which is what lets the Studio start on a private network at all. The
   measurements below stand as the record of what was accepted.
2. **Old links keep working.** The Svelte Studio's hash routes — `#chat/…`,
   `#factory/…`, `#projects/…`, `#runs/…`, `#settings/…` and the rest in
   `lib/routes.ts` — are translated to the new places by the Flutter
   Studio's router, from a table with a test per route. A hash it does not
   know opens Overview with a one-line notice. `/next/…` redirects permanently
   to the same place at `/`, so an old link still opens what it named.
3. **What is removed.** `web/ui/` entirely; the Svelte build in
   `web/bridge/static`; `tsgen` and `contract.ts`; the CI web job; the
   browser checks that drive Svelte; the Node setup in every workflow; the
   `web/ui` instructions in `AGENTS.md`.
4. **What replaces it.** The Flutter web build is written to
   `web/bridge/static` by a documented command and embedded by the same
   `go:embed`. CI builds it there and then builds `webbridge`, so the embed is
   compiled on every run. A Go-only checkout keeps a committed placeholder
   index, because the real build is a 10 MB engine plus assets whose hashed
   names churn on every build. CI also fails on a tracked `*.svelte` file or a
   Node project under `web/`. The boundary test `TestWebIsStdlibOnly` is
   unchanged: it concerns Go.
5. **End-to-end coverage moves, it is not dropped.** Each check in
   `scripts/e2e` that drives the Svelte Studio is either re-expressed
   against the Flutter Studio or shown to be covered by a phase's own
   end-to-end suite, in a table in this phase's implementation record. The
   checks that drive the bridge's HTTP directly stay as they are.
6. **Size and start-up are recorded, and have a ceiling.** The record
   states the `webbridge` binary size before and after, the bytes
   transferred on first load, and time to first usable screen on a phone
   over a private network. If first load is more than three times the
   Svelte Studio's, that is raised as a decision before removal, not
   after.
7. **The mock goes.** `docs/studio-flutter/mock/` and `screenshots/` are
   deleted; `design.md` loses its mock section and gains current
   screenshots of the real app.
8. **Documents.** `AGENTS.md`: commands, the map, the web control plane
   section and the native app entry. `docs/ARCHITECTURE.md`.
   `docs/web-studio/README.md` and `design.md` gain a header saying the
   Studio's UI is now described in `docs/studio-flutter/` and that their
   page specifications are history; their backend and contract sections
   stay current. `docs/testing-ci-audit.md`. `app/README.md`.
9. **The tray's "Open Fleet" stays**, and "Open Studio" from F2 is the
   first item.

## Trial measurements

Taken on the trial build with the roles swapped (Flutter at `/`, Svelte at
`/classic/`), 2026-11-17, on the development host — the numbers that deferred
the cutover (revised decision 1). With the roles as they now stand, the
Flutter rows are what `/next/` serves and the Svelte rows are what `/` serves;
no row changed. First load is each Studio's `index.html` plus every
byte it fetches before its first screen. **The bridge compresses nothing** —
there is no `Content-Encoding` on any route in `web/bridge` — so the browser
receives these bytes raw; the gzip column is what a compressing proxy would
send, and is the lower bound.

| Measure | Svelte raw (gz) | Flutter raw (gz) |
|---|---|---|
| `index.html` | 413 (290) | 2,079 (1,041) |
| App bundle | 1,584,992 (471,374) | 3,088,278 (911,086) |
| Styles / bootstrap | 54,591 (11,735) | 14,407 (5,772) |
| Rendering engine | — | 7,402,483 (2,955,524) |
| Fonts | 52,528 (52,657) | 1,208,916 (555,856) |
| **First load** | **1,692,524 (536,056)** | **11,716,163 (4,429,279)** |

**The Flutter app-bundle figure was re-measured at the swap's HEAD
(`02c3b041`).** An earlier draft of this table recorded 2,940,163 raw
(870,764 gz) for it; that number came from an earlier app state and is not
what this branch builds. Two `flutter build web --base-href /` runs at HEAD
produce `main.dart.js` at 3,088,278 bytes (911,086 gz) both times, and every
other row is unchanged, so the table above is the trial's Studio rather than
an approximation of it. The correction makes the over-ceiling case slightly
stronger, never weaker; the decision below does not change.

`webbridge`, built here with both Studios' real output embedded: 66,372,191
bytes. With the Svelte tree as it ships and the Flutter placeholder, the same
build is 22,622,960 bytes — the difference is the 42 MB of build output the
embed takes in, not the swap. The swap itself moves no bytes: the two trees
keep their sizes and only their prefixes change. Removal (Task 4) is what
shrinks the binary, by the 2.3 MB Svelte tree. That binary figure was taken
with the earlier app build too; only `main.dart.js` has moved since, and it is
148,115 bytes larger, so a build today would be about that much bigger.

**First load is 6.9× Svelte's raw (8.3× compressed), over the ceiling in
decision 6 (3×)** — raised here, before removal, as the plan requires.

Two facts about that number decide what it means:

- **7.4 MB of it is the rendering engine, which does not come from the
  bridge.** The build fetches CanvasKit from `gstatic.com/flutter-canvaskit`
  unless it is made with `--no-web-resources-cdn`, and neither workflow passes
  that flag, although `app/web/flutter_bootstrap.js` says they should. So a
  browser that has CanvasKit cached from any other Flutter site fetches none
  of it, and the app-served figure is 4,313,680 raw (2.55×) — inside the
  ceiling. A first visit is what is over.
- **The same fact breaks the private-network case.** On a network that cannot
  reach `gstatic.com`, the engine never arrives and the Studio does not start
  at all. That is the phone-over-a-private-network measurement the plan asks
  for, and it currently cannot pass.

Time to first usable screen **on a phone was not measured**: this host has no
browser and no phone (see the environment-blocked list). The byte counts stand
in for it until one does.

## End-to-end checks: the accounting table

Decision 5 moves coverage rather than dropping it. Every check in group I of
`scripts/e2e/checks_spa.py` and every Playwright spec, against what holds now
that the Studio is the Flutter one.

| Retired check | Now |
|---|---|
| `scripts/e2e/run_browser_checks.sh` and the `*.pw.ts` specs | deleted with the Svelte build they drove. Their subjects — the shell's routes, deep links, roadmap, and the project and factory settings surfaces — are the app's own widget and integration tests' business (`app/test/`, `app/integration_test/`), which reach the widget tree directly instead of a CanvasKit canvas |
| "the shell is served and names its assets" | re-expressed as **"the root document is the Studio's index"**: HTML, carrying the Studio's title, and not the retired Svelte one |
| "every asset the shell names resolves" | re-expressed as **"the Studio's bootstrap resolves"**. The document names `flutter_bootstrap.js` relatively, so the check resolves it against `/`. A Go-only checkout embeds the placeholder, and the check skips there instead of passing vacuously |
| "content-hashed assets are immutable" | dropped: Flutter emits unhashed asset names, so the shell names no content-hashed file. The predicate is pinned directly by `TestLooksHashed` in `web/bridge` |
| "the served bundle normalizes a pasted token" | covered by `app/test/client/transport_web_test.dart`: `normalizeToken` strips a pasted `Authorization:` prefix and a `Bearer` scheme, which is the behaviour the bundle grep looked for |
| "the served bundle bounds prompt declines"; "stops on a rejected token" | dropped: the Flutter Studio signs in with a single-use code the bridge hands over, not a stored token prompt, so neither the decline guard nor the rejected-token state exists to check |
| "index.html is never cached"; "client-side routes fall back"; "unknown /api paths 404 as JSON"; "every /api route demands a bearer"; "the bearer prefix is not doubled"; "/mcp authenticates per client"; "previews are not on the UI origin" | unchanged: they are the bridge's contract, and its routes and auth did not move |

New in the group: **"the Studio does not fetch its engine from a CDN"** fails
when a served build names gstatic. That is the defect that left the Studio
blank on a private network, and it is invisible on a development host with a
route to the internet.

## Fixed while the trial was running: the browser Studio reached nothing

Serving the Flutter build at `/next/` was not enough to use it. Opening it
showed the Studio's background and no fleet: five defects, none of them in the
build that F8 changed, all of them on the path a page takes to its bridge. They
were found by driving a headless browser at the served page and reading what it
rendered, since nothing in the app's own tests crossed them (each is a
platform-conditional seam or a request shape a fake accepted).

- **Discovery found no host.** `host_discovery_stub.dart` returned `const []`
  with a comment saying the browser reaches the bridge that served the page
  "which F2 wires up". Nothing wired it, so a browser had no host, no fleet and
  no rows. The stub now answers the page's own origin as one `HostKind.server`
  host, and nothing for a page no bridge served.
- **The token was read from the wrong key.** `TokenStoreWeb` reads
  `marshal:bridge-token`; the Svelte Studio at `/` stores the same bridge's
  token under `marshal:token` (`web/ui/src/lib/api.ts`). A browser already
  signed in at `/` therefore sent no bearer token at `/next/` and every
  `/api/` route answered 401. The Svelte key is now read as the fallback.
- **The fleet stream asked for the wrong route.** `fleetEvents()` requested
  `/api/events`; the bridge reads that as a session's stream and refuses it
  without a `sessionId` (400). The stream is the query-selected
  `?stream=fleet` view.
- **An open stream was silent, so an idle host never read as live.** The fleet
  stream replays nothing to a fresh client and heartbeats every 25s, so a
  healthy connection sent nothing at all for 25s; the client counts a line as
  contact, so it reported `unreachable`. `ServeSSEKey` now writes one
  `: connected` comment line before its first flush.
- **The staleness window was shorter than the heartbeat.** `staleAfter`
  defaulted to 10s against a 25s beat, so even after the first heartbeat a live
  idle stream was declared stale between beats. The default is now 35s
  (`EventStream.defaultStaleAfter`), and the tests that advance a fake clock
  over a shorter window name it themselves.

Verified by serving the built bundle from a bridge and loading it in headless
Chromium with the Svelte Studio's token in storage: every `/api/` route 200s,
the accessibility tree carries the shell (places, the `marshal` project, the
Overview's counts), the host reads `live`, and there are no console errors.
Not covered: a real phone on a private network, and the token-prompt path when
neither key holds one (the host then reads `unauthorized`, honestly).
