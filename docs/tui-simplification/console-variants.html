Five ways to build the console

The same session at the same moment as round 1: a busy turn at 96 × 34, plan 2/4, a reviewer subagent and a background test run. History is identical in every variant except Streaming, so only the dock changes.

  • History only grows
  • Tint and a coloured edge mark running work, and only running work
  • Finished work lands in history as one event
  • The plan is always visible

At a glance

Streaming's history rows include the live step's narration and finished calls, which the other docks hold in the dock.

Recommendation: Streaming. It is the simplest of the five: one rule (nothing above the in-flight call ever changes), the smallest dock, and no step moving from dock to history when it settles. If running work needs to stand out more, Shelf's cards drop into Streaming's dock unchanged.

Why it can stream

  • Round 1's closing └ had to be rewritten whenever another call arrived. A rail (│) never changes.
  • So the narration and each finished call append to history the moment they complete.
  • The in-flight call sits directly under them, so the step reads straight across the boundary.

Good

  • The smallest dock and the most history.
  • History is the whole story; nothing jumps when a step settles.
  • The simplest wire: appended lines plus a small live payload.

Costs

  • No drawn border between history and live work. The spinner, the tint and the plan row carry it.
  • The step loses its visible end marker.
  • The plan is one stepper row.

Good

  • The most unmistakable look for running work.
  • Two cards cost the same 4 rows as one.
  • Each card has room for a second activity line.

Costs

  • A third card needs a second shelf row or a +1 card.
  • Coloured borders put a lot of colour on screen.
  • The plan is a stepper.

History styles

The grammar of history is separate from the dock. The same step, four ways.

Spine · round 1

Membership drawn, end marked. The closing └ must be rewritten when a call arrives, so it cannot stream.

● Adding the retry loop around doRequest with jittered backoff.
├ edit internal/llm/client.go+38 −6
├ shell go build ./internal/llm/...exit 0
└ shell go test ./internal/llm/ok · 41 tests

Rail

Same membership, never rewritten. The next ● or a blank line ends the step.

● Adding the retry loop around doRequest with jittered backoff.
│ edit internal/llm/client.go+38 −6
│ shell go build ./internal/llm/...exit 0
│ shell go test ./internal/llm/ok · 41 tests

Hook

Each result on its own line under its call. Twice the rows per call.

● Adding the retry loop around doRequest with jittered backoff.
edit internal/llm/client.go
⎿ +38 −6
shell go build ./internal/llm/...
⎿ exit 0
shell go test ./internal/llm/
⎿ ok · 41 tests

Gutter

Verbs right-aligned in a left gutter, like a log. Scans fast down the verb column; narration loses some width.

Questions

  1. Which dock, or which mix? The pieces are separable: Streaming's dock with Shelf's cards and Split's plan, for example.
  2. Which history style? Spine, rail, hook or gutter.
  3. What didn't work in round 1? The separation between history and dock, the plan, the running rows, or the history grammar?
