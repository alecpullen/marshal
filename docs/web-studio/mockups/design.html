Marshal · web UI design · high fidelity

Marshal Web Studio Design

The chosen direction drawn in detail: the session layout that merges the workbench with the focus and inspector views, the pages you picked, and six new feature pages. All sample data is illustrative.

Agent sessionHome & live wallNew agentReview & shipRunsWorkspacesWatch monitorsNetwork inspectorPR review botCI fixerShared memoryStatus pageMultiple users

Decisions so far

  1. Home is the inbox, with a separate Live wall page. New agent is prompt first. Review & ship is pull-request style.
  2. Runs have stage lanes and a task graph. Workspaces use the layer builder, with the source file editable next to it.
  3. Agent session merges the workbench and focus + inspector options into one layout, shown in four states below.
  4. The Warm Sunset theme stays. The design leaves room for multiple users (owners, avatars, roles), but building it comes later.
01

Agent session: one layout, four states

The transcript stays in the centre and follows the TUI's rules. To its right is a dock, which replaces both the workbench and the inspector drawer. The dock has the same tabs in every state (Inspect, Changes, Files, Terminal, Preview), and two things decide what it shows:

  • Size: collapsed (focus), docked (about 440px), or expanded (about 65% of the width, with the transcript shrinking to an outline).
  • What it follows: the agent while nothing is selected, or your selection once you pick a step or tool row with a click or browse keys. Esc, or "back to live", returns it to following the agent.

The inspector isn't a separate drawer any more. It's the Inspect tab while you have something selected. The other tabs follow the selection too: Changes filters to the hunks the selected step made, and Terminal jumps to the output of the selected command. You can pin a tab so a selection doesn't switch it.

Multiple users: designed for, built later

The pages above already leave room for more than one person, so adding users later won't need a redesign:

  • Avatars and origins on agents, approvals, comments and memories (you, a schedule, CI, a teammate).
  • "Mine / Everyone" on Home and lists. With one operator, "Mine" is everything.
  • An owner field on agents, runs, workspaces, secrets and memories, from day one in the data model. The bridge already has DefaultOwnerID.
  • Roles to arrive later: viewer, operator, admin. Every action is already designed as a single operation that can be checked against a role and written to the audit log.

Deferred: user accounts, sign-in, single sign-on, role enforcement, per-user notifications and shared team memory.
